# Living School Social Simulation Engine

Социальный и когнитивный вертикальный срез автономного социального симулятора на Python 3.12+. Десять **синтетических неканонических** персонажей: игрок и девять NPC. Игрок бездействует, NPC сами приглашают друг друга, принимают или отклоняют приглашения, встречаются, сообщают о встречах и реагируют на возможное исключение.

## Запуск

```bash
cd /workspace/gpt3
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
source .venv/bin/activate
python -m social_sim validate data/fixtures
python -m social_sim run --scenario data/fixtures/school.yaml --days 30 --seed 42 --no-player
python -m social_sim explain --run output/run_42 --event-id e000001
python -m social_sim resume --snapshot output/run_42/snapshot.json --days 5 --output output/continued
python -m social_sim batch --scenario data/fixtures/school.yaml --days 30 --seed 40 --count 10
python -m pytest -q
python -m mypy social_sim
```

Для повторного запуска используйте новый `--output`: CLI защищает существующие результаты от перезаписи. `--days` у resume — дополнительные дни. Действий за игрока без явного внешнего ввода нет; интерактивный UI пока отсутствует. `--no-player` явно обозначает этот режим, который также используется по умолчанию.

В каталоге прогона: `events.jsonl`, `traces.jsonl`, `snapshot.json`, `relationships.json`, `metrics.json`. `explain` показывает выбранное действие, оценки альтернатив, знания на момент решения, случайный выбор и непосредственные причины события. Это отладочная информация разработчика, а не взгляд игрока. Связанные причины можно последовательно открывать той же командой.

## Причинный пример

Двое знакомых встретились в парке → третий ничего не знает → один участник рассказал ему о встрече → убеждение об исключении и ожидания приглашений сформировали субъективную интерпретацию → появилась обида → возросла полезность вопроса или дистанцирования. Спокойный профиль интерпретирует тот же факт нейтрально. Движок не утверждает, что исключение было намеренным. Ответ на вопрос зависит от знаний, доступности и решения адресата. Подтверждение встречи не опровергает исключение; релевантное объяснение может частично изменить оценку. Версии интерпретаций, память и причины пересмотра сохраняются.

Приглашение создаёт будущий план. Организатор резервирует слот; адресат самостоятельно решает, подходит ли предложение. Во время уроков встреч нет. Повтор приглашения тому же человеку ограничен восемью слотами; за свободный слот возможна одна инициатива. Короткие ответы на обращения учитываются отдельно. Совместный опыт изменяет направленные отношения, отсутствие общения само по себе их не уменьшает.

## Когнитивный срез: задачи 0–6

Реализованы социальные ситуации с историей свидетельств, ограниченная значимая память, переоценка после разговора и устойчивое намерение дистанции. После cooldown NPC не повторяет реакцию без нового эпизода. Все политики используют единые веса. Снимки имеют **версию 2**; снимки первого прототипа v1 отвергаются, YAML-досье остаются v1.

```bash
python -m social_sim run --scenario data/fixtures/school.yaml --days 30 --seed 42 --no-player --output output/my_cognitive_run
python -m scripts.inspect_cognitive_examples --output output/my_examples
python -m social_sim explain --run output/my_examples/explanation --event-id e000005
python -m social_sim resume --snapshot output/my_cognitive_run/snapshot.json --days 5 --output output/my_continuation
```

Скрипт примеров создаёт шесть контролируемых контрастов: подтверждение, объяснение, отказ, повторный эпизод, слабые знакомства и спокойный профиль. В них ответы игрока на приглашение заданы явно, а реакцию наблюдателя и ответ собеседника выбирают NPC. Это технические фикстуры, не написанная история игры. Существующие каталоги результатов защищены от перезаписи.

`social_initiatives` теперь считает invite/tell/ask/distance; прежнее число приглашений доступно как `invitation_initiatives`. Ответы учитываются отдельно. Низкая инициатива NPC с потребностью в независимости допустима. Подробные результаты, три разобранные причинные цепочки и границы модели — в [отчёте](docs/validation.md).
