# Блоки A и B: контракты

## A: эпизоды и разговоры

Состояние оценки хранится по эпизодам встречи внутри ситуации. Эмоция ситуации — сводка эмоций эпизодов, уверенность — максимум актуальных подозрений. Ответ пересматривает только subject_event; объяснение старой встречи не оправдывает новую. Новый факт сохраняет distance_active и статус обсуждения, пока есть ожидающий вопрос. Каждый вопрос остаётся отдельным событием в очереди; закрывается конкретным ответом. Дистанция прекращается при ослаблении суммарной эмоции либо явном решении вступить в разговор/завершении ситуации. Форма JSON проверяется до чтения world.schema_version.

A принят: 104 pytest pass, mypy strict 11 модулей; воспроизведения и сохранение сразу после сообщения проверены. Контролируемые примеры confirmation/explanation/refusal сохранены в output/block_a_examples. Исходная точка bc57cb1 совпала с аудитом: 86 тестов, 207 приглашений, 91 встреча, 93 отказа.

## B: знакомства

Посредник выбирает пару из собственных знакомых. Политика не получает граф чужих связей и может предложить уже знакомых людей; движок сообщит об этом без изменения отношений. Предложение конкурирует в utility и имеет стоимость и cooldown. Стороны отдельно выбирают согласие; игрок молчит без ввода. Успешное событие создаёт только отсутствующие направления со слабой близостью. Имена в чужих событиях не создают знакомства. Старые сведения и закрытые планы не раскрываются.

## B: планы

Единственный источник ответа — dict replies[invitee], содержащий status и личную историю invitation/response. План содержит организатора, время и общий журнал переходов. Отдельный адресат знает только своё приглашение/ответ. При наступлении времени участвуют организатор и согласившиеся; остальные получают expiry, при отсутствии согласий план закрывается без встречи. Парные act invite и respond без invitee сохраняются. Групповое приглашение: invite_group(actor, invitees). Для нескольких адресатов respond требует invitee. Приглашать группу политика может только из собственных знакомых; детектор компаний ей недоступен.

## B: компании

Диагностический детектор строит максимальные клики взаимных связей (минимум три человека) с взаимной близостью >=40 и минимум двумя совместными встречами за последние 32 слота. Общий знакомый и слабый мост не объединяют клики. Пересечения допускаются. Проверка раз в день, изменения требуют двух последовательных подтверждений; короткая пауза внутри окна не меняет состав. Параметры настраиваются через GroupSettings сценария. Составы сопоставляются по максимальному пересечению (минимум два общих участника), затем Jaccard и ID; однозначное сопоставление даёт стабильный ID при изменении состава. Точные совпадения всех текущих составов резервируют свои ID до сопоставления по пересечению; новая группа не забирает ID неизменившейся. Смена ID сама по себе не считается событием. История хранит tick, состав и основания (пары, события, пороги). Удаление активности компании не снижает личные отношения.

## Форматы

Снимок v3: новые оценки по эпизодам, групповые планы, знакомства и диагностическая история компаний. v1/v2 явно отклоняются без догадок. YAML остаётся v1 с опциональными настройками. Формальные чаты в текущих фикстурах не нужны и не имитируются фактическими группами. Список компаний существует только в WorldState/диагностике, не в ActorView.

Знакомство требует явного introduction_completed. Встреча с незнакомцем не создаёт ребра в обход согласия; эффекты применяются к уже знакомым парам. Новый эпизод сохраняет старую очередь даже после следующей реакции distance. Ни источник ролей, ни порядок личных ответов не дают NPC глобальное знание.
