# Добавление тестового персонажа

Сценарий — YAML версии `schema_version: 1`. Пример полного рабочего документа: `data/fixtures/school.yaml`. В `people` добавьте уникальный ID (`[a-z][a-z0-9_]*`), имя, `biography`, `synthetic: true`, `is_player: false` и `personality`. Ровно один участник сценария должен иметь `is_player: true`.

В `personality.traits` обязательно явно задать все 24 характеристики из спецификации, каждую целым числом 0–5. Пропуски, лишние поля, bool и строки вместо чисел отвергаются. Не копируйте синтетические значения в канон без авторского согласования.

Поддерживаемые убеждения `beliefs`: `id`, `condition: friends_met_without_me`, `interpretation: excluded`, числовая `strength` 0–1 и авторское `description`. Убеждение срабатывает лишь после получения факта встречи двух знакомых без наблюдателя; свободный текст не исполняется. Стратегии `strategies` — `ask`, `distance`, `invite`; они меняют оценки, а не принуждают к действиям. Цели `goals`: `kind: connect` или `preserve_autonomy`, `priority` 0–1. Это упрощённая модель целей первого среза; сроки, прогресс и условия завершения пока не моделируются.

Начальные связи задайте в `relationships`: `source`, `target`, `liking`, `trust`, `closeness`, `tension`, `romantic_interest`, `perceived_reciprocity`. Шкалы 0–100. Обратная связь задаётся отдельно; отсутствие обратной записи не запрещено. Обычная инициатива адресуется знакомым; посредник может предложить познакомить два собственных контакта, а стороны решают отдельно. Романтический интерес сохраняется как данные и не участвует в выборе.

Постоянная личность отделена от энергии, одиночества, обиды, cooldown, знаний и памяти. Время: 0 — утро, 1 — учёба, 2 — после уроков, 3 — вечер; следующий день начинается с нового кратного четырём слота. Еженедельное расписание и выходные ещё не моделируются.

`weights` позволяет менять множители `need`, `personality`, `goal`, `relationship`, `emotion` (0–5) и окно `selection_band` (0–20, не включая 0). Множители применяются централизованно во всех политиках: инициативы, рассказ, ответы на приглашение и вопрос. Соответствие компонентов категориям описано в architecture.md. При весе 0 численный вклад исчезает, жёсткое предусловие остаётся. Все компоненты видны в traces. Trait-поля, пока не используемые в формулах, сохраняются для следующих срезов, а не изображаются готовыми механиками. В частности, унижение, конформность, верность и биографический опыт ещё не обработаны отдельными правилами.

## Внешнее действие игрока

```python
from pathlib import Path
from social_sim.authoring import load_scenario
from social_sim.engine import Simulation

sim = Simulation(load_scenario(Path('data/fixtures/school.yaml')), seed=42)
sim.step()  # утро
sim.step()  # уроки
sim.act('player', 'invite', 'n1')
sim.run_days(30)
```

Адресат использует обычную политику и вправе отказать. `respond(plan_id, accept=True/False)` позволяет подать внешний ответ на приглашение; параметр используется также контролируемыми тестами. Без `accept` ответ выбирает NPC. В API нельзя повторять инициативу в том же слоте, действовать во время уроков или принимать несовместимую встречу. `share_information(sender, receiver, event_id)` передаёт только факт, уже известный отправителю; повторная доставка идемпотентна. Мир предназначен для отладки, UI должен читать только знания игрока.

## Дальнейшее согласование

Технический сценарий не определяет личности четырёх канонических NPC и организатора. До их добавления потребуется согласовать досье, убеждения, личные границы и стартовые отношения. До сцен — тон и допустимые варианты. Текущий срез не требует этих решений.


## Ситуации, память и обстоятельства

Черты теперь представлены глубоко неизменяемой моделью Traits; форма YAML осталась прежней. Для изменения профиля создайте новый валидируемый Scenario, а не меняйте объект во время симуляции.

Не всякое знакомство порождает ожидание приглашения. Нужны близость и симпатия не ниже 30 либо релевантная история. Организатор встречи задаётся явно движком; перестановка массива участников не меняет адресата. Каждая ситуация содержит актуальную версию интерпретации, известные свидетельства, эмоцию и предпринятые реакции. Величина hurt — вычисляемая сводка, её нельзя назначать отдельно от причины.

Опциональное поле сценария `meeting_context: no_prior_group_plan` задаёт **синтетическое** обстоятельство для встреч данного сценария. По умолчанию unknown. Участник может сообщить известное обстоятельство при ответе; получатель не знает его до сообщения и учитывает доверие источнику. Это не утверждение о честности или скрытом намерении. Пример — `data/fixtures/cognitive.yaml`.

Обычные встречи попадают в память с темой companionship; предполагаемое исключение и объяснение — exclusion. Рабочая память ограничена 24 записями; для решения извлекаются до пяти релевантных. Параметры ранжирования и влияния централизованы в memory.py. Не добавляйте фиктивные эпизоды ради обязательной драмы.

`sim.act('n3', 'ask', 'n1', defer_reply=True)` сохраняет незавершённое обсуждение; следующий свободный step обрабатывает ответ. `accept=None` у respond запрещён для игрока: хост должен подать его явный ответ. Повторная передача уже известного факта не создаёт эмоций или свидетельств.

Текущие снимки v4 несовместимы с v1–v3 без отдельной миграции. Диагностические traces содержат собственную границу событий; знания из будущего не подставляются в прошлое объяснение. Для нового прогона всегда используйте новый output.


## Знакомства, группы и API

`data/fixtures/social_world.yaml` содержит десять синтетических участников: ядро со стартовыми знакомствами и более разреженные связи с дополнительными школьниками. Треугольник знакомых в ядре не является фактической компанией без достаточной истории встреч. Сценарных дат знакомств/распада нет.

```python
# В свободном слоте, каждый организатор имеет одну инициативу.
sim.introduce('n4', 'n1', 'n7')
# Обе стороны выбирают ответ; для игрока без ввода результат не считается согласием.
# В контролируемых тестах допустим answers={'n1': True, 'n7': False}.

plan = sim.invite_group('n1', ['n2', 'n3', 'player'])
sim.respond(plan.id, True, invitee='n2')
sim.respond(plan.id, False, invitee='n3')
# Игрок молчит: при наступлении времени его приглашение истекает.
```

Это независимые примеры: нельзя вызвать две инициативы одного NPC в одном слоте. Прежние `act(actor, 'invite', target)` и `respond(plan_id, accept)` остаются для парного плана. Для группового ответа invitee обязателен. Повтор ответа или meet после исполнения отвергается атомарно. Для применения выбранного DecisionTrace используйте `execute_decision(trace)`; он умеет новые инициативы introduce/invite_group.

Опциональные настройки сценария:

```yaml
group_settings:
  closeness: 40
  meetings: 2
  window_slots: 32
  confirmations: 2
```

Компанией считаются минимум три участника максимальной клики с достаточной взаимной близостью и историей каждой пары. Движок проверяет группы раз в день; два последовательных подтверждения стабилизируют изменения. Короткая пауза внутри окна не меняет состав. Нельзя выводить из отсутствия фактической активности, что дружба исчезла: личные шкалы не убывают ежедневно.

group_changes — диагностические переходы, не авторские сюжетные события. Их members/previous_members различают реальное изменение состава и реактивацию того же состава. ActorView не включает список компаний и чужие ответы. Формальные чаты в текущей фикстуре не используются и автоматически из детектора не создаются.

Контекст встречи с незнакомцем не отменяет ожидания от известного близкого организатора. Незнакомые участники остаются только именами известного факта; чужие планы и отказы не раскрываются. В v3 сохраняются оценки отдельных эпизодов, все ответы, очередь вопросов, новые связи с причинами, история компаний и RNG.


## Недовольство, поддержка и извинения

Новая неканоническая фикстура — `data/fixtures/relationship_repair.yaml`: десять явно заданных участников, без расписания конфликтов. Числа и изменения черт в ней — механические тестовые контрасты, не биографии канонических героев.

После известной неприятной встречи можно передать обращение:

```python
request = sim.interact('n3', 'support_request', 'n4', meeting_id,
                       about='n1', defer_reply=True)
sim.respond_interaction(request.id, 'n4', 'acknowledge')
# n4 теперь знает сообщение n3 о переживании, а не сам закрытый факт встречи.
support = sim.interact('n4', 'support', 'n3', meeting_id, defer_reply=True)
sim.respond_interaction(support.id, 'n3', 'accept')
```

Это пример API после необходимого знакомства, получения факта и собственной интерпретации n3; meeting_id должен быть реальным. Инициатор может выполнить одну инициативу в свободный слот, ответ имеет отдельную стоимость. Для извинения:

```python
apology = sim.interact('n1', 'apology', 'n3', meeting_id,
                      content='regret_hurt', defer_reply=True)
sim.respond_interaction(apology.id, 'n3', 'defer')
```

n1 должен предварительно получить сообщение от n3 об этом эпизоде, где n1 — обсуждаемый участник. `acknowledge_act` дополнительно требует известного собственного участия; `regret_hurt` выражает сожаление о переживании, не неизвестном умысле. API отвергает неверный адресат, предмет или неподходящий ответ до изменений мира и RNG.

Ответы: discontent → acknowledge/disagree/decline; support_request → acknowledge/decline; support и apology → accept/decline/defer. Без defer_reply NPC обычно отвечает сразу, если свободен и есть бюджет. Игрок остаётся pending до явного respond_interaction; UI не требуется. Completed означает ответ на обращение, а не дружбу без остаточной обиды.

Одна и та же попытка не даёт повторного эффекта. Новая известная совместная встреча после предыдущего обращения допускает повторную попытку после ответа/истечения; отсутствие ответа не заменяется чтением глобального статуса. Если эффект принятия уже применялся к этому эпизоду/источнику/типу, новый ответ не увеличивает доверие повторно. Сам совместный опыт меняет отношения обычным правилом.

Память repair_attempt сохраняет факт известной попытки восстановления, даже если ответ ещё не принят. Её влияние ограничено общей выборкой пяти воспоминаний вместе с exclusion; она не стирает отрицательную историю. Отказ не штрафуется, признание переживания не устанавливает вину, а поддержка третьего знакомого не оправдывает другого человека.

Формат YAML не изменён. Снимки — v4; не используйте старый v3-снимок как начальное состояние с выдуманными обращениями. Для проверки: `python -m scripts.inspect_relationship_repair --output output/new_examples`.
